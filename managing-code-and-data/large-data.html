Large Data

When working with research data, files can become quite large, such as high-resolution images, genomic sequences, or climate model outputs. Storing these large files directly in a Git repository poses several challenges. Git is designed to track changes in text-based files efficiently, but large binary files can bloat the repository size, making cloning, pushing, and pulling operations slow and resource-intensive. Moreover, Git stores the entire history of all files, so even if a large file is later removed, its history remains in the repository, contributing to ongoing storage costs.

Popular platforms like GitHub impose limits on repository and file sizes to ensure performance and cost-effectiveness. GitHub caps individual files at 100 MB by default, requiring the use of Git Large File Storage (LFS) for larger files. Repository sizes are limited to 5 GB for free accounts, with higher limits available on paid plans (up to 50 GB or more depending on the tier). Exceeding these limits can prevent pushes, trigger warnings, or require repository cleanup, migration to paid plans, or the use of external storage solutions. These constraints are particularly relevant for research projects dealing with large datasets, as they can disrupt workflows and increase costs.

To handle large data effectively, several tools extend Git’s capabilities for versioning large files without compromising repository performance. Below, we discuss three approaches: Git LFS, DVC, and gitxet.

Git LFS

Git LFS (Large File Storage) is an open-source Git extension that replaces large files with text pointers inside Git, while storing the file contents on a separate server. This keeps the repository lightweight while maintaining version control for large files. Git LFS is widely supported and integrates seamlessly with Git workflows.

For IIASA researchers, a self-hosted GitLab instance is available that circumvents the data size limitations of GitHub. Git LFS is supported on this instance without additional payment, making it suitable for managing large research datasets. To get started, register an account with your institutional email and set up two-factor authentication as detailed in the GitLab page.

To use Git LFS, install the extension from its official website. For Windows users, the standard Git installer from git-scm.com includes Git LFS as an optional component that can be selected during installation. If not selected, download and run the separate Git LFS installer from the Git LFS site. Once installed, track large file types with commands like git lfs track "*.dat". This is suitable for teams already familiar with Git, as it requires minimal changes to existing workflows.

Git DVC

DVC (Data Version Control) is a tool that builds on Git to version data and models, treating them as first-class citizens alongside code. Unlike Git LFS, which stores large files on the same server as the repository, DVC requires you to arrange your own backend storage, such as Amazon S3, Google Cloud Storage, or a local server. This separation allows for potentially higher performance, as data can be stored in optimized cloud storage systems, and DVC handles versioning and synchronization.

DVC is particularly useful for machine learning projects where data pipelines need to be reproducible. It integrates with Git to track data changes and supports features like data lineage and experiment management. However, setting up backend storage adds complexity, as you’ll need to configure access credentials and manage costs for cloud storage.

For more information, visit the DVC website. DVC is open-source and can be installed via pip or other package managers.

gitxet

gitxet is an emerging Git extension designed for handling large files and datasets, developed by XetHub. It aims to provide high-performance versioning for massive datasets, with features like on-demand file access and efficient storage. Currently, gitxet is still in active development and is primarily used in the context of Hugging Face, a platform for sharing and collaborating on machine learning models and datasets.

Hugging Face (huggingface.co) is an open-source community and platform that hosts a vast library of pre-trained models, datasets, and tools for natural language processing and other AI tasks. gitxet enables efficient management of the large model files and datasets hosted there, allowing users to version and share them without the overhead of traditional Git.

While promising, gitxet is not yet as mature or widely adopted as Git LFS or DVC, so it may require more technical expertise to set up and troubleshoot. For the latest developments, check the XetHub website or Hugging Face’s documentation.
